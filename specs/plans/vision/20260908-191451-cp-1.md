## Architecture decisions (tagged)

- **DERIVED**: `com.ticketing` is the root package, `ticketing-platform` the Maven
  artifact id, matching the vision's "Event Ticketing Platform" — the single Maven
  module that will eventually host the rest of the vision (out of scope here). This
  keeps the pom/module identity stable for future planning tasks that extend the same
  module.
- **DERIVED**: `{event}` in `GET /api/v1/quotes/{event}/{tier}` is treated as an opaque
  `String`, not parsed into `UUID`. Requirement 22 declares only `404`/`422`/`503` for
  this endpoint (unlike requirements 7/8/15/19/20, which additionally declare a generic
  `400`). Parsing `{event}` as a strict UUID would introduce an undeclared `400` on
  malformed input. Treating it as an opaque key and returning `404` ("no price for
  scope") for any non-matching value satisfies the declared status set exactly.
- **DERIVED**: `{tier}` is bound as a raw `String` and parsed explicitly inside the
  endpoint's service layer (Task 7), not via Spring's automatic `@PathVariable` enum
  conversion. Automatic enum conversion failures surface as Spring's own
  `MethodArgumentTypeMismatchException` → `400` by default, which conflicts with the
  spec's declared `422` for "unknown tier". Explicit parsing keeps the "parse, don't
  validate" boundary (requirement 27) in one place and produces the documented status.
- **ASSUMPTION** (ordering/wiring convention, ≤60s to change, ok under Rule 2's medium
  budget): `PriceChanged` is delivered to its consumer via Spring's
  `ApplicationEventPublisher` + `@TransactionalEventListener(phase = AFTER_COMMIT)` +
  `@Async` — option (a) of the two acceptable implementations in
  `specs/vision.md#constraints` ("Domain facts"). This task does not implement a
  producer (pricing writes are out of scope), so Task 6's consumer is tested by
  publishing `PriceChanged` directly. Any future task that implements the pricing-write
  producer (`POST /pricing/set`, `POST /pricing/adjust` — both out of scope here) must
  publish through the same `ApplicationEventPublisher` mechanism for this consumer to
  receive events; if that task instead adopts the outbox-poller option (b), the
  consumer wiring here will need to change from an event listener to an outbox-row
  reader. This is a single, reversible integration point, not a critical-path
  assumption over irreversible state.
- **DERIVED**: The `price_view` table/projection built here is distinct from the
  `current_price` projection in `specs/vision.md#domain-model`, which backs the
  *authoritative* `GET /pricing/quote/{event}/{tier}` (requirement 12, out of scope).
  `price_view` is a second, independently-lagging, eventually-consistent read model
  fed only by the `PriceChanged` fact, per requirement 22's "independent projection"
  framing — it does not read or write `current_price`.
- **DERIVED**: No Spring Security is configured in this task. The only endpoint in
  scope is `public`; nothing in this scope needs to be restricted, so there is nothing
  for a security filter to guard yet. Requirement 28's build-time "no undeclared access
  level" enforcement mechanism is a whole-application, multi-role invariant that only
  becomes meaningful once `role:admin` / `role:authenticated` / `role:operator`
  endpoints exist (all out of scope here); building that mechanism now for a single
  public endpoint would be speculative infrastructure (Rule 6).
- **DERIVED**: Persistence uses `spring-boot-starter-jdbc` (`JdbcTemplate`), not
  `spring-boot-starter-data-jdbc`. A single hand-written guarded `UPSERT` statement
  does not need a repository-abstraction layer; `JdbcTemplate` is the smaller
  dependency that still satisfies `specs/vision.md#constraints` ("Spring Data JDBC or
  `JdbcTemplate`").
- **ASSUMPTION** (non-critical, reversible): exact Spring Boot 4.x patch/minor version
  and Testcontainers/Flyway versions are left to implementation time (latest stable
  compatible with Java 25 at that point) — pinning a specific patch version now would
  likely be stale by the time Task 1 is coded.

## Task breakdown

### Task 1 — Maven/Spring Boot project skeleton

**Desc**: Create the Maven/Spring Boot 4 project skeleton (pom.xml targeting Java 25,
main application class, application.yml) that compiles and boots an empty Spring
context

**Done when**: `mvn -q -DskipTests package` succeeds producing
`target/ticketing-platform-*.jar`; `TicketingApplicationTests` (a `@SpringBootTest`
asserting the application context loads) passes via
`mvn -q -Dtest=TicketingApplicationTests test`; `pom.xml` declares Java 25
(`maven.compiler.release=25`), a Spring Boot 4.x parent, and
`spring-boot-starter-web`, `spring-boot-starter-jdbc`, `flyway-core`,
`flyway-database-postgresql`, `org.postgresql:postgresql`, `spring-boot-starter-test`,
`org.testcontainers:postgresql`, `org.testcontainers:junit-jupiter` dependencies plus
`maven-failsafe-plugin` bound to the `integration-test`/`verify` phases for `*IT.java`
classes; `application.yml` externalises the PostgreSQL datasource URL/username/password
via environment-variable placeholders

**Scope**: `pom.xml`; `src/main/java/com/ticketing/TicketingApplication.java`;
`src/main/resources/application.yml`;
`src/test/java/com/ticketing/TicketingApplicationTests.java`. No business logic, no
controllers, no persistence code. This task is the sole owner of `pom.xml` and
`application.yml` for the whole plan — no later task in this plan touches either file.

**Spec ref**: `specs/vision.md#constraints` (Language / runtime, Framework, Build,
Persistence, Config)

**Depends on**: none

### Task 2 — Money value type

**Desc**: Add the Money value type: an immutable non-negative long minor-unit amount
paired with a closed Currency enum (USD, EUR, GBP), rejecting negative amounts at
construction

**Done when**: `MoneyTest` passes via `mvn -q -Dtest=MoneyTest test`, asserting:
`Money.of(0, USD)` and positive amounts construct successfully; `Money.of(-1, USD)`
throws `IllegalArgumentException`; two `Money` instances with equal amount+currency are
equal (value semantics); `Money` never exposes or accepts a `double`/`float`

**Scope**: `src/main/java/com/ticketing/domain/Currency.java`;
`src/main/java/com/ticketing/domain/Money.java`;
`src/test/java/com/ticketing/domain/MoneyTest.java`. No HTTP/DB coupling.

**Spec ref**: `specs/vision.md#domain-model` (Money — non-negative integer minor
units, currency closed set USD/EUR/GBP, never a floating-point type)

**Depends on**: Task 1 (needs the Maven module to exist to compile/test)

### Task 4 — DomainException base + central HTTP-status mapping

**Desc**: Add a DomainException base class carrying its own HTTP status and a central
`@RestControllerAdvice`/`ProblemDetail` exception handler that maps any DomainException
to its declared status and maps `org.springframework.dao.DataAccessException` to 503,
so no known failure path returns a generic 500

**Done when**: `GlobalExceptionHandlerTest` passes via
`mvn -q -Dtest=GlobalExceptionHandlerTest test`, using a throwaway `@RestController`

HTTP 404 response; a subclass declared with 422 yields 422; a subclass declared with

`ProblemDetail` JSON bodies

**Scope**: `src/main/java/com/ticketing/domain/DomainException.java`;
`src/main/java/com/ticketing/web/GlobalExceptionHandler.java`;
`src/test/java/com/ticketing/web/GlobalExceptionHandlerTest.java`. No concrete domain
exception subclasses beyond test fixtures — endpoint-specific exceptions (e.g.
`PriceNotFoundException`) are owned by Task 7.

**Spec ref**: `specs/vision.md#constraints` (Error mapping — central handler maps
each typed domain failure to its documented HTTP status code, never a generic 500)

### Task 6 — price_view projection + PriceChanged consumer

**Desc**: Add the price_view projection (Flyway migration + repository) and an
idempotent, version-guarded consumer that applies PriceChanged events to it via a
single guarded UPSERT

**Done when**: `PriceViewProjectionIT` (Testcontainers PostgreSQL) passes via
`mvn -q -Dtest=PriceViewProjectionIT verify`, asserting: (a) the first PriceChanged for
a (event, tier) scope inserts a `price_view` row with its amount/currency/version; (b)
a subsequent PriceChanged with a higher version updates the row; (c) a PriceChanged
with a version less than or equal to the row's current version leaves the row
unchanged; (d) redelivering the same PriceChanged event twice is a no-op (idempotent)
— all verified against the guarded UPSERT SQL, not application-level compare-then-write

**Scope**: `src/main/resources/db/migration/V1__create_price_view.sql`;
`src/main/java/com/ticketing/quote/PriceView.java`;
`src/main/java/com/ticketing/quote/PriceViewRepository.java`;
`src/main/java/com/ticketing/quote/PriceChangedProjector.java`;
`src/test/java/com/ticketing/quote/PriceViewProjectionIT.java`. No HTTP controller —
that is Task 7. `PriceChangedProjector` listens for `PriceChanged` via Spring's
`ApplicationEventPublisher`/`@TransactionalEventListener(phase = AFTER_COMMIT)`/`@Async`,
per `specs/vision.md#constraints` option (a); no producer is implemented in this task
(pricing writes are out of scope).

**Spec ref**: `specs/vision.md#5-customer-quote-read-model-independent-projection`
(requirement 22 projection clause, requirement 23)

**Depends on**: Task 1, Task 2 (Money), Task 3 (PriceTier), Task 5 (PriceChanged event)

### Task 7 — GET /api/v1/quotes/{event}/{tier} endpoint

**Desc**: Add GET /api/v1/quotes/{event}/{tier}, a public endpoint returning the
customer quote from the price_view projection

**Done when**: `QuoteServiceTest` and `QuoteControllerTest` pass via
`mvn -q -Dtest=QuoteServiceTest,QuoteControllerTest test`, asserting: (a) happy path —
an existing price_view row for (event, tier) returns 200 with body
`{event, tier, amountMinor, currency, version}` matching the row; (b) no price_view row
for the scope returns 404 via `PriceNotFoundException`; (c) a tier path segment that is
not one of the 5 PriceTier constants returns 422 via `UnknownPriceTierException`,
parsed once at the boundary (no `PriceTier.valueOf` leaking a raw
`IllegalArgumentException` as 400/500); (d) a `PriceViewRepository` failure (simulated
via a fake throwing `DataAccessException`) returns 503; all three failure paths use
fakes, no DB

**Scope**: `src/main/java/com/ticketing/quote/QuoteController.java`;
`src/main/java/com/ticketing/quote/QuoteService.java`;
`src/main/java/com/ticketing/quote/QuoteResponse.java`;
`src/main/java/com/ticketing/quote/PriceNotFoundException.java`;
`src/main/java/com/ticketing/quote/UnknownPriceTierException.java`;
`src/test/java/com/ticketing/quote/QuoteServiceTest.java`;
`src/test/java/com/ticketing/quote/QuoteControllerTest.java`. No Spring Security
configuration — the endpoint is unrestricted by default since no
authenticated/role-based endpoint exists yet in this scope; full access-level
enforcement (requirement 28) is out of scope. The `{event}` path segment is treated as
an opaque string key (no format/UUID validation), matching requirement 22's declared
status set (404/422/503 only, no 400).

**Spec ref**: `specs/vision.md#5-customer-quote-read-model-independent-projection`
(requirement 22)

**Depends on**: Task 1, Task 2 (Money), Task 3 (PriceTier), Task 4 (DomainException +
mapping), Task 6 (price_view projection)
